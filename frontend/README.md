# 墨记

基于 uni-app、Vue 3、TypeScript 和 Pinia 的微信记账小程序前端。使用 **HBuilderX 标准项目目录**，直接导入本目录即可开发。微信 AppID：`wx0f90babab478b2b6`。

## 在 HBuilderX 中运行

1. 使用支持 Vue 3 的 HBuilderX 正式版，通过「文件 → 导入 → 从本地目录导入」选择 `frontend`，不要选择整个仓库或 `unpackage`。
2. 第一次运行先在此目录执行 `npm install`，安装项目依赖。
3. 在 HBuilderX 的「工具 → 设置 → 运行配置」中设置微信开发者工具路径，并在微信开发者工具的「设置 → 安全设置」中开启服务端口。
4. 在 HBuilderX 中选择「运行 → 运行到小程序模拟器 → 微信开发者工具」。编译目录为 `unpackage/dist/dev/mp-weixin`。
5. 微信开发者工具中使用拥有此 AppID 开发权限的微信账号登录。首次打开进入墨记登录页；「先体验一下」无需后端，「微信登录」需先运行 `backend/run.py`。前端不保存 AppSecret。

登录页已接入真实微信登录，提供加载状态、失败提示和重试。「我的」提供登录入口、登录状态、账号称呼及退出按钮；再次启动会先请求后端校验保存的凭证，再恢复账号。退出时调用后端注销当前 token，网络失败会保留当前状态并提示重试；凭证过期或收到 401 后回到登录页。

后端地址由 `common/config.ts` 中的 `appConfig` 统一管理，通过 `uni.getAccountInfoSync()` 识别微信小程序的运行版本：

| 运行版本 | 后端地址 |
| --- | --- |
| `develop`（开发版） | 本地开发地址，默认 `http://127.0.0.1:8000` |
| `trial`（体验版）、`release`（正式版）、未知版本 | `https://mjzs.zf-yun.cn` |
| 版本信息缺失、读取失败或非微信平台 | 默认按开发版处理，使用本地开发地址 |

前端无需 `.env` 文件，开发地址和正式地址直接在 `common/config.ts` 的 `DEV_BASE_URL` 与 `PROD_BASE_URL` 中配置，修改后重新编译生效。默认开发地址适合本机微信开发者工具与 PyCharm 联调；真机开发需改为手机可访问的本地开发服务器地址。发布构建也按运行时版本判断，体验版和正式版都使用正式域名。

本地 HTTP 调试需在当前开发者工具项目中配置域名校验，正式 `manifest.json` 仍保留 `urlCheck: true`。体验版和正式版需在微信公众平台将 `https://mjzs.zf-yun.cn` 添加为 request 合法域名。

登录后个人及共享账本、账单和预算保存在云端，页面进入或返回前台会重新读取，也可下拉或手动刷新；请求失败不转成本地保存，暂不提供离线写入。体验数据保留在 `moji-demo-v1`；云端缓存使用 `moji-cloud-v1:<后端地址>:<用户ID>:ledger`，昵称仍按用户隔离。原 `moji-user-v1:<用户ID>:ledger` 保留原样，如有记录，「我的」提供旧记录 CSV 导出，不自动上传。首次登录创建空的日常账本，退出后恢复体验区。共享邀请、成员权限及生命周期已部署正式后端，登录账号不生成模拟成员或账单，详见[共享账本说明](../backend/docs/shared-books.md)。

登录凭证按后端地址分别缓存，不打印 code 或 token。若开发工具热重载保留旧 store，清除**编译缓存**并重新编译，不需要清除数据缓存。接口契约见[微信登录说明](../backend/docs/wechat-login.md)。

2026-10-24 已通过微信开发者工具实际点击登录页和「我的」入口完成真实登录，验证冷启动恢复、界面退出、退出后 token 返回 401，以及原有体验账单未被改写。登录及云端记账另有 `npm run check:auth` 的自动检查，覆盖失败重试、401、离线、账号切换、存储不足和迟到响应。

如 HBuilderX 提示缺少 Sass 编译插件，按提示安装。建议使用与本项目锁定的 uni-app CLI 编译器相同或更新的 HBuilderX 正式版；构建依赖以 `package-lock.json` 为准。

```text
frontend/

│   │   └── shared-books.ts        # 多人账本规则与本地体验逻辑
│   ├── styles/

│   ├── types/
│   │   └── index.ts               # 账本、账单、分类与成员类型

├── components/          # 导航、账单列表、图表和弹层等组件
├── pages/               # 登录、明细、统计、账本、我的、记一笔、墨记助手、日历、多人账本
├── static/              # 本地 SVG 图标，不依赖远程图片
├── store/               # Pinia 状态和本地存储
```

## 已实现的交互

- 明细：月份与账本切换、收入/支出切换、分类筛选、备注/账户搜索。
- 消费日历：从明细标题右侧「日历」进入，支持「全部、支出、收入」三种模式，默认同时展示每天的支出（−）和收入（+）。切换模式后，月汇总、日格、当日明细和无记录提示同步变化；支出与收入分别按整数分汇总，不相互抵减。支持月份与账本切换、回到今天、按选定日期补记，收入模式补记默认选择收入。无对应记录显示「—」，大额日格使用缩写，精确金额在当日明细中查看。
- 记账：自定义金额键盘、分类、日期、账户、账本、备注；新增、编辑、确认删除。
- 统计：分类环形图、日均金额、七日趋势和分类排行；数据与当前账单同步。
- 账本：账本切换、新建账本、独立收支与预算。
- 多人账本：从「我的账本 → 多人账本」进入，创建共同账本，体验家庭示例与受邀加入，查看共同收支、成员及各成员的记录，预览、重新生成或撤销演示邀请。创建者可移出普通成员并设置共同预算；普通成员仅维护自己的账单。移出成员会保留历史账单和记账人，并撤销该账本现有演示邀请。共同账单不允许转移到其他账本。
- 我的：微信登录入口与状态、账号称呼、退出登录、预算、分类、CSV 导出和帮助；体验模式可恢复演示数据。
- 墨记助手：一句话记账和聊天分析两个页面模式，从首页、记账页或统计页进入。

## 墨记助手

首页提供「一句话记账」和「聊聊花费」入口。微信登录后，一句话记账将输入文本发送到后端的 sub2api，使用 `gpt-6-luna` + 固定 `xhigh` 生成可编辑草稿；确认前不写入账单。体验模式继续使用预置示例。聊天分析已支持根据云端账单自由提问、连续追问和历史会话，模型继续使用固定 `xhigh`。

2026-10-27 工作区已将「一句话记账」改为聊天界面，支持连续补充及单张图片识别；对应后端已部署至 `20261027T052736Z`，小程序界面尚未上传体验版。可输入文字、拍照或从相册选取截图/小票，支持图片配文字；信息不足时继续补充。当前待确认草稿会随对话更新，旧卡片保留为失效快照；需点击卡片才能保存。记账对话只在当前页面保留，详见[文字聊天与图片记账](../backend/docs/conversational-record.md)。

「聊聊花费」使用 SSE 流式接口：先显示统计卡，再逐句追加经过数值校验的解释；微信端通过分块请求接收，H5 使用 fetch 流式读取。单轮服务端预算默认 240 秒，前端等待 300 秒，解释失败仍保留统计。断流时标记预览尚未确认保存，可重新读取或用原消息 ID 重试；切换账号、账本、月份会取消旧连接。后端 `20261026T050441Z` 已发布，用户已确认小程序体验版 `1.0.9` 发布，真机效果尚未由本任务验收，详见后端 `docs/chat-analysis.md`。

- 一句话记账：输入或点选示例后点击发送；登录后可连续说「改成32元」「是昨天的」，也可发送图片生成草稿。支持修改金额、收支类型、分类、日期、时间、账户和备注，逐笔确认、批量确认或忽略。确认后写入当前账本，登录账号保存到云端，明细、统计和 CSV 导出同步更新，已确认的草稿不会重复保存。
- 示例「今天早上八点吃早餐8块钱」包含 `08:00` 时间。未给出时间的账单不补造时间，未给出账户时明确使用默认账户。现有账单兼容可选时间字段。
- 聊天分析：点选示例问题，展示当前账本的分类占比、分类明细、月度对比、超过200元的支出和消费提示。登录账号由后端查询真实云端账单并计算金额、占比和差额，模型负责解释，连续追问可继承分类、月份和收支类型；体验区保留本地示例。统计页进入时保留所选月份，首页进入时使用当前月份。
- 登录后支持任意自然语言记账，金额缺失或日期有歧义时提示补充；未提供时间保持空值，默认账户明确展示并允许修改。自由聊天已支持按自然月分析；周、日、年度等范围会要求补充月份。通过「历史」可继续当前账本及入口月份最近的对话，「新对话」保留旧历史；失败后可重试原消息或重新读取，分析对话不修改账单。登录账号的完整问答保存在云端，重新进入恢复最近对话；体验对话仅保留在本次页面中。

演示逻辑位于 `common/mock/assistant.ts`，交互组件位于 `components/assistant/`，记账对话状态位于 `store/record.ts`。新记账通过 `store/ledger.ts` 请求 `/api/v1/assistant/record`，旧 `/parse` 保留兼容，确认复用普通账单接口；前端不保存模型密钥。图片读取在 `common/services/record-image.ts` 中处理，单张最多4 MiB，支持 JPG、PNG、WebP。接口约定见[文字聊天与图片记账](../backend/docs/conversational-record.md)。

体验模式首次运行以当天为基准生成演示账单。此后体验区读写本地存储，不会反复填充或重置数据。金额以整数分保存。当前账户仅是账单标签，不管理资金余额；预算为各账本的固定月预算。

**个人及共享记账、智能识别已部署正式后端，小程序体验版已发布，用户已确认双账号真机测试完成。** 登录后可创建共享账本、生成与撤销邀请、管理成员、查看操作记录、退出/转让/解散账本。体验区的示例家人与邀请不是实际用户，仅在主动体验时创建，不自动上传。旧本地账单及升级前未上传的记录仍保存在设备上，清理存储或卸载会丢失这些数据；「恢复演示数据」仅覆盖体验区。真实共享的接口与验收见[共享账本说明](../backend/docs/shared-books.md)。

## 可选的命令行检查

这些命令与 HBuilderX 使用同一份根目录源码，仅作为构建验证和辅助预览，无需将项目改成 `src` 目录结构。

```powershell
npm ci
npm run check
npm run dev:mp-weixin
npm run build:mp-weixin
```

`npm run check` 依次运行 TypeScript 检查和 `check:auth`、`check:chat`、`check:assistant`、`check:calendar`、`check:shared-books`、`check:shared-cloud`；任一失败立即停止并返回非零退出码。功能检查使用模拟服务或内存数据，各单项命令仍可独立运行。共享账本检查复用 `scripts/test-modules.mjs` 递归解析本地模块及 `@/` 别名，新增依赖无需逐项手写替换。

在仓库根目录执行 `.\scripts\check.ps1` 可统一检查前后端，追加 `-Build` 同时验证微信小程序和 H5 构建，前置依赖和真实集成验证说明见[项目说明](../README.md#开发与检查)。

开发模式输出 `unpackage/dist/dev/mp-weixin`，发布构建输出 `unpackage/dist/build/mp-weixin`，可手动导入微信开发者工具。H5 仅辅助检查移动布局，微信开发者工具和真机才是小程序验收环境。

```powershell
npm run dev:h5
npm run build:h5
```

本地图标可通过 `npm run generate:icons` 重新生成。

### 小程序提示模块缺失或页面未注册

如果出现 `module 'common/config.js' is not defined`，并伴随 `Component is not found`、`Page "pages/login/index" has not been registered yet`，先处理最早出现的模块加载错误，页面和组件错误可能是后续连锁反应。

当前请求模块为 `common/api/request.ts`，编译后引用 `common/config.js`；若错误堆栈仍出现旧路径 `common/api.js` 或 `common/auth.js`，说明正在加载旧产物。先停止当前编译任务，在 `frontend` 目录执行 `npm run dev:mp-weixin`，等待 `Build complete`，再让微信开发者工具打开 `unpackage/dist/dev/mp-weixin`。也可以在 HBuilderX 停止运行后重新「运行到微信开发者工具」。

确认导入目录下存在 `common/config.js`、`common/api/request.js` 和 `pages/login/index.js`。若工具仍报告旧路径，清除微信开发者工具的**编译缓存**后重新编译；无需清除数据缓存，本地账单保存在其中。不要手动在源码中补建 `config.js`，它由 `common/config.ts` 编译生成。

登录页正常显示后，若出现 `127.0.0.1:8000 ... ERR_CONNECTION_REFUSED`，需启动本地后端 `backend/run.py`，并确认开发地址和服务监听端口一致。
