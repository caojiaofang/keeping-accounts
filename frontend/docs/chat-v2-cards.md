## 结果展示

`components/assistant/cards/ResultCard.vue` 负责当前范围、比较范围、筛选条件、部分状态及更新时间；汇总、账单、趋势和差额分别由四个子组件展示，事实共用 `FactList.vue`。

- 金额、总笔数、差额、增长率和占比都显示服务端事实。前端只计算趋势条的相对长度，不重新汇总账单或推算增长率。
- 账单卡分开显示全部匹配合计、全部匹配笔数与本卡展示笔数。当前回答协议不携带工具分页游标，因此本步没有增加“加载更多账单”按钮，也不会把二十笔展示当成全部匹配结果。可继续按日期或条件追问缩小范围。
- 趋势条对应实际返回的日期；缺失日期不补零。差额保留负数与超过 100% 的贡献，明确区分数值变化与生活原因。上期日期及按日对齐说明直接显示服务端返回内容。
- 显示收支、分类、备注关键词的任意/全部匹配、排除词、账户、记账人、金额开闭边界、星期及指定排除笔数。分类及成员名称按当前账本映射，历史成员无法映射时显示“历史记账人”；不声称名称也保存在历史快照中。
- 时间按设备本地时间显示到秒；统计是生成时的历史快照，不随查看账单而修改。空列表、长备注、部分完成及多个结果卡均有明确展示。

动态追问继续使用已保存消息的建议 ID 与原文；受控来源由后端恢复和校验，客户端不拼接工具参数。未保存预览的账单入口禁用，部分已保存回答仍可查看实际返回的账单。

## 当前账单与权限

点击真实账单 ID 后进入新增的 `pages/entry/index.vue` 只读详情页。`ledger.readEntryReference(id, bookId)` 每次调用既有鉴权 `GET /api/v1/ledger`，从最新有效账本和记录中定位该 ID，并再次核对发起时的账号、token、账本与本地写入版本。请求失败不会改用聊天数据或本机缓存打开。

这里复用现有完整账本快照接口，没有新增后端路由；数据量很大时可后续单独优化为鉴权单笔读取接口。本次不扩展模型所接收的数据。

详情页区分加载、删除/移出账本、成员失效及网络错误；账号/账本变化、页面隐藏或卸载会清除当前展示并忽略迟到结果。再次显示页面会重新读取。共享账本成员可查看他人记录，编辑按钮依照当前权限显示。点击编辑会重读，编辑页通过 `fromChat=1` 再核对一次并保留当前版本；最终写入仍由既有后端权限和乐观锁保证。失效引用不会打开空白新增表单。

## 阅读和键盘

在底部时跟随新快照、正文及最终消息；用户上滑后停止跟随，显示“回到最新内容”。主动发送、点击建议、重试、切换历史或点击返回最新内容时回到底部；本轮等待中再上滑，最终回答到达时仍保持阅读位置。

加载更早消息后定位到原来的第一条消息。保留 textarea 的 `adjust-position`、`cursor-spacing` 和底部安全区；键盘高度、输入行数及页面重新激活时重新测量阅读区。

## 2026-11-06：等待响应时列表闪动修复

用户视频中，“回到最新内容”反复出现和消失，列表随之上下跳动。原按钮位于聊天滚动区外的纵向 flex 布局中，出现时挤占列表高度；高度变化又产生滚动事件，导致跟随状态反复切换。本地 H5 测量确认，原布局的按钮出现时会使聊天区缩短 38px。

`ExpenseChat.vue` 改为固定高度的聊天容器，将返回按钮放在该容器内的绝对定位浮层，显示与隐藏不再占用列表高度。自动滚动只监听回答预览、正文及正式消息数量变化，等待阶段的进度文字更新不再重复清空、重设滚动锚点。

验证使用本地虚构身份、两轮历史和二十笔账单，不请求真实模型或业务数据：

- 390px 与 320px 下分别连续更新等待文字、追加流式预览，确认等待时列表位置稳定；上滑阅读后，返回按钮保持显示、列表位置不被预览更新打断；点击返回后正常到达底部。
- 390px 的等待及阅读视口均为 545px，320px 均为 488px；各阶段的连续采样中，视口高度与阅读位置变化均为零。按钮显示、隐藏不再改变视口高度。
- 首次窄屏测试碰到 uni-app 在浏览器 resize 后异步换算 rpx 的时序，验收脚本加入布局稳定等待后复测通过；该等待仅用于测试，不是业务页面中的延迟处理。
- 前端完整 `npm run check`、微信小程序及 H5 构建通过。H5 验收脚本、日志和截图在本机忽略目录 `output/playwright/chat-flicker-*` 与 `output/chat-flicker/`。
