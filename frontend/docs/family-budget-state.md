2026-11-06，第 07 步完成。需求和进度见[总计划](../../docs/家庭预算功能与分步开发计划.md)，后端规则见[契约](../../backend/docs/family-budget-contract.md)与[账单执行](../../backend/docs/family-budget-execution.md)。本步接入运行时数据层，没有新增页面、升级数据库或发布。

## 1. 模块与调用

- `common/api/budget.ts`：完整预算 API，包括方案预览／保存、月份确认／覆盖、精确均摊、项目发现／双分页详情、资金／目标、关联和月度执行。复用现有 apiRequest、Bearer、401 处理和中文错误，DELETE 关联使用 JSON 正文；路径和查询值编码。
- `store/budget.ts`：独立 Pinia store，plan/month/execution/projects/detail 分别保存。`load()` 读取当前账本／月的基础数据，`loadDetail()` 读取项目，`query(method, ...args)` 用于其他只读查询及预览，`write(method, ...args)` 负责写入和刷新，`retry()` 重放失败的原请求。
- `common/services/budget-demo.ts`：独立本地体验数据源，支持方案、快照、覆盖／均摊、资金审计、目标、账单关联、分页与执行计算；`createFamilyBudgetExample()` 只生成草稿和新 UUID，不自动采用或上传模板。
- `store/ledger.ts`：把当前账号、凭证、账本、成员信息、月份及云端就绪状态连接到预算 store。账单或权限变化使旧预算失效；已读取的执行按需重载，budgetNotice 单独保留为 notice。

写入由调用方在操作开始时调用 `newRequestId()`，同时固定完整请求正文中的业务 ID 与版本。网络失败后调用 `retry()`，不能重新生成 requestId。资金版本、月版本、方案版本和关联墓碑版本各自读取、各自提交；取消关联后不能退回 linkVersion=0。

## 2. 隔离与可靠反馈

预算云端数据仅保存在当前运行内存中，不落一份跨账号可复用的预算缓存。上下文绑定服务地址、账号、token、完整账本权限信息、月份和就绪状态；任一变化清空旧视图并递增代次，迟到的读取／写入响应不会回填新上下文。同账号换 token 也重建数据源。

读取校验 schemaVersion、bookId 和月份归属，禁止把另一账本响应当成当前数据。并发加载只应用最新批次，项目详情有独立请求序号。loading 与 writing 表示实际请求状态，账号切换清理旧请求标志。

写入不乐观增加现金或伪造成功。一般方案／资金／目标操作复用创建者权限检查；关联复用可编辑账单权限；后端仍负责最终鉴权。网络／503 类错误保留冻结的路径、正文和 requestId，显式重试原请求；409 标记 conflict、清空旧视图并要求读取最新版本，不自动改版本再提交。401／403／404 清除失效视图。

成功写入后刷新方案、月份、项目列表、月执行及原打开详情，expense 关联即使没有 fundVersions 也刷新消费。刷新失败使用 refreshError「已保存，最新预算读取失败」表达，不将保存成功伪装成写入失败，也不再重试一次存入。重复点击进行中的写入不会发送第二个请求。

原记账仍使用已有输入，budgetNotice 不写入账单备注。前端页面在后续步骤订阅 notice/error/conflict/refreshError，显示相应提示。

## 3. 体验模式

体验数据只使用 `moji-budget-demo-v1:{bookId}`，与原体验账单、云端账号和 token 存储分开。首次预算为空；主动保存方案后才有预览，确认才有快照，资金须明确记录。登录不会上传体验预算；云端失败不会回退到体验成功。

体验消费引用现有体验账单，use 按有效关联派生。修改、删除、改为收入或日期不合法后重算用途资金，不制造第二份收入／消费。期初只计一次，替代修正保留原记录；结转只分配实际资金，不增加余额。精确均摊按整数分分配，快照固定基础方案，单月覆盖完整替换；操作异常或存储失败回滚该次修改。

体验保存和幂等凭据都在本地，服务端仍是云端业务的权威实现。本地体验不模拟 PostgreSQL 行锁、共享生命周期竞争或服务器故障，不以本地通过替代真实数据库及设备验收。模板日期使用体验当天，具体实际缴费日期由后续表单明确填写。
