## 接口

以下路径都位于 `/api/v1/assistant/v2`：

| 方法与路径 | 行为 |
| --- | --- |
| `GET /capabilities` | 已认证用户读取支持版本及开关 |
| `POST /conversations` | `{id,bookId,initialMonth}` 创建 V2 会话；相同 ID、账本、入口月份可重试 |
| `GET /conversations?bookId=<UUID>` | 当前账号、当前可访问账本最近二十个有已保存回答的 V2 会话，不按入口月份过滤 |
| `GET /conversations/{id}?before=<sequence>` | 默认最近二十轮；`before` 为严格小于的序号，最小为 1；结果按序号升序 |
| `POST /conversations/{id}/messages/stream` | `{id,text,suggestionId?}`，只提供 SSE 消息入口，消息文本最多二百字符 |
| `GET /legacy/conversations/{id}?before=<sequence>` | 同一账号及可访问账本的旧会话只读适配，不改写原记录 |
| `POST /legacy/conversations/{id}/fork` | 新建同账本 V2 会话，只继承旧筛选；请求为新的 `{id,bookId,initialMonth}` |

会话摘要包含 `schemaVersion/id/bookId/initialMonth/title/updatedAt`。历史响应另含 `context/turns/hasMore`：顶层 `context` 始终是当前权威成功上下文，即使请求的是较早一页，也不能用旧页最后一轮覆盖当前范围。消息仍为 `TurnResponseV2`，卡片、建议、事实、完整性及生成时间一并恢复。

旧会话适配响应格式为 V2，额外明确 `sourceSchemaVersion=1/readonly=true`；正文按原始快照显示，不伪造新卡片。通过普通 V2 历史或发送接口不能继续写入旧会话，须先 fork。V1 列表及读取排除 V2 会话，新协议不会写到旧结构上。

## 消息流及确认

首包前验证登录、会话及当前账本权限；失败返回普通 HTTP 错误。后续失败通过 SSE 的 `error` 返回，HTTP 已经是 200 时，客户端必须读取事件中的状态。

| 事件 | 含义 |
| --- | --- |
| `status` | 公开进度，例如理解问题、核对账单、保存回答，不展示模型推理 |
| `ping` | 模型或数据库等待期间每十秒保活，数据为 `{}` |
| `snapshot` | 当前完整预览，整份替换已有预览，不能追加卡片 |
| `delta` | 追加已验证正文的完整段落，不转发上游原始草稿或半个占位符 |
| `done` | 完整 `TurnResponseV2`；轮次已提交，覆盖预览 |
| `error` | `{status,detail}`，本次没有确认完成；保留原消息 ID 供读取或重试 |

当前实现等待可信回答准备完成后，先发送包含全部卡片/事实及空正文的快照，再发送已验证正文段落，随后用完整快照统一替换，最后保存并发送 `done`。查询等待期间先展示状态并发送心跳，不声称模型逐 token 正文已经接入。

单次消息处理的锁、限流、模型查询、预览及保存共享整轮期限。回答准备沿用原 deadline，保存不能重新获得一份超时预算。SSE 队列有界；断连取消生产任务，等待模型连接、数据库事务和 Redis 锁清理完毕后，才结束请求依赖。

收到卡片、正文或完整快照都不代表保存成功。取消发生在提交前时不写入半轮；如果已经提交但 `done` 未送达，消息已经存在，下次读取或同 ID 重试会返回原结果。

## 幂等、并发和权限

- 保存前后使用同一消息 UUID。首次查到已保存消息就直接重放 `done`，不再次调用模型、占用会话锁或计入新提问限流。
- 同 ID 改变正文或建议 ID 返回 409，引用其他会话的消息 ID 返回统一 404。
- 新消息取得 Redis 会话锁后再次查重，避免等待前后发生竞态。与 V1 共用同一账号限流键和同一会话锁键，不能换接口绕过限制。
- 每账号每分钟最多十次新提问，会话最多一百个已保存轮次；锁有效期为整轮预算加六十秒，释放时检查随机令牌，不能误删其他请求的锁。
- Redis 故障不降级为无锁执行，明确返回 503；并发忙返回 409，限流返回 429。临时服务故障不是零记录。
- 数据库会话版本 CAS、轮次唯一约束及消息主键共同防止重复保存。查询、输出新内容及提交前复核权限；共享成员能看账本不代表能看其他成员的私有聊天，成员失权后旧会话也不能继续读取。

## 部分结果如何保存

保留既有字段，无新增表或迁移：`context.schemaVersion=2` 标记协议，`ChatConversation.version` 是所有已保存轮次的并发版本，包括部分结果；它不表示权威上下文一定处理到相同序号。

| 状态 | 消息历史 | 权威会话上下文 |
| --- | --- | --- |
| 完整成功 | 保存正文、卡片、事实与已验证建议 | 原子更新完整筛选、比较范围、摘要、结果引用 |
| 明确部分完成 | 保存 `completeness=partial` 和非空 `missing`，不保存可执行建议 | 保留上一成功上下文，版本与消息序号仍前进 |
| 普通失败、超时、提交前取消 | 不保存半轮 | 不改变 |

`save_success` 继续拒绝部分结果；新 `save_turn` 显式区分两类保存。部分消息的 `context` 也是上一成功状态，临时查询范围在其卡片中保留。模型近期问答排除部分轮次，摘要不吸收部分结论；默认“这笔”解析跳过部分轮次，显式从部分轮次恢复筛选、建议或账单引用也会拒绝。

`done` 和 `completeness` 含义不同：`done + partial` 表示“部分结果及缺失说明已经保存”，不代表完整结论。相同 ID 再试仍重放该部分消息；要继续补查，用新消息 ID，按当前成功条件重新提问。该规则也覆盖部分消息的 `done` 丢失。
