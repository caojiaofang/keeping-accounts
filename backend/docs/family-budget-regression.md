## 1. 可重复运行的入口

在项目根目录、Docker Desktop 已启动且前后端依赖已安装的环境执行：

```powershell
.\scripts\check-budget-integration.ps1
.\scripts\check.ps1 -Build
```

隔离入口创建随机名称的 PostgreSQL 17 容器，仅绑定 `127.0.0.1` 随机端口，数据目录使用 tmpfs。测试库固定为 `moji_budget_migration_test`，每个场景使用随机 schema；迁移从空库到 `0006_budget`。退出时恢复相关环境变量、停止并移除自己的容器，不改动已有数据库或其他容器。不要求 Redis、模型或微信账号。

入口只运行六个预算集成文件，不能改为设置集成开关后执行全部 pytest；其他模块的专用集成测试可能依赖真实外部服务。前端 HTTP 联调由 `test_budget_frontend_integration.py` 启动临时 Uvicorn 服务，再启动 Node 执行 `frontend/scripts/check-budget-integration.mjs`。真实前端模块经 uni.request 传输适配器访问该回环端口，所有预算、账单路由、正文、响应及 SQL 事务均实际执行；测试身份仅替换令牌解析。独立运行 Node 文件缺少隔离配置时会失败，不加入默认离线检查。

## 4. 发现的问题与修复

1. **账单刷新打断预算保存。** 新增检查先复现 `writing` 被提前解除，旧响应被代次丢弃。修复为在途写入只使读取视图过期，保留写入锁，成功后统一重读；同账号同 token 的重复激活不再无条件使预算失效。
2. **未知结果被新请求覆盖。** 数据层拒绝在 `retryAvailable` 时开启另一笔写入，只能重试原冻结请求；刷新和页面返回保留待重放类型与正文。
3. **离页后月确认误报调整完成。** 原确认请求可重放，但新页面已没有未提交的单月表单。设置页现在明确提示原计划已确认、单月调整尚未提交，要求重新填写预览；不会把确认结果冒充覆盖保存成功。
4. **离页重试入口消失。** H5 实测发现总览刷新清除了错误字符串，但未确认请求还在，设置页因仅依赖错误文字显示按钮而成为空页。修复为只要仍可重试就展示恢复提示与按钮，与错误字符串独立。
5. **固定月额与周期预计值缺少具体比较。** 按验收矩阵补齐 520×12 与 6,100 的 140 元差额，以及 4,200 的半年／全年计划提示。明确它们不是实际存款，也不覆盖单月安排。

## 5. H5 实际交互

本机最终生产 H5 构建连接专用回环 HTTP 服务及临时 PostgreSQL schema。浏览器只替换登录校验、令牌与目标传输地址；没有把请求发送到公开服务。

- 页面实际读到 15,600／15,600／0 和零实际。
- 将单月人情 400 改 600，先确认原月计划时注入提交后断连。返回首页／总览再进设置，重试入口可见；重试后明确「原计划已确认、单月调整尚未提交」，人情仍 400，不显示 600 已保存。该流程先复现问题再修复复测。
- 项目详情进入正常记账后直接取消，返回提示没有新增支出，用途资金为零。
- 停留记账页时通过隔离接口模拟另一设备新增两笔实际支出，返回后提示核对关联，不自动打开单笔确认或派生 use；通过真实详情接口核对余额和已用仍为零。
- 320px 恢复界面与 390px 详情截图已人工查看，布局无横向溢出。最终构建在 390px 重新载入后，模板提示实际显示 6,240／140 和 25,200／50,400。

本次故障注入会产生预期网络失败及 API timeout 警告；此外只有初次静态预览 favicon 404，没有观察到应用运行时异常。截图保存在忽略目录 `output/playwright/family-budget-step11/`，不是发布产物；临时服务、浏览器和专用数据库容器验后清理，已有用户容器未停止。
