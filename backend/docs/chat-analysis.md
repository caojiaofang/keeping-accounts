## 功能与统计口径

登录后「墨记助手 → 聊聊花费」使用真实云端账单，可自由提问分类分布、分类明细、大额收支、前月对比和消费建议，支持收入查询。追问可继承最近成功回答的月份、分类和收支类型。例如「餐饮具体花在哪了」后接「这一类和上个月同期相比呢」，仍只分析餐饮。

- 只查询当前登录用户有权访问的个人或共享账本，排除已删除记录。共享账本汇总所有成员的有效账单，会话仍为每用户私有；跨账号、跨账本会话不可读取。每轮、历史读取及模型返回后均重新验证权限，成员失效后不能继续获取新回答或历史。
- 本月截至上海时间的今天，排除本月未来日期的记录；已结束的月份按完整自然月计算。
- 本月与上月默认按同期比较，上月天数不足时截到月末；用户明确要求上月全月时，展示两个实际查询区间。历史月份与前月按完整月比较。
- 金额始终以整数分累计；分类占比保留一位小数；大额筛选为严格超过阈值，未指定阈值时默认超过 200 元。
- 明细最多显示金额最高的二十笔，总额与笔数包含全部匹配记录。分组、明细和月份对比均用单条业务查询保证卡片内部数值一致。
- 查询目前以单个自然月为单位；周、日、全年等范围会要求补充月份。分析对话不修改账单，记账、修改和删除仍需通过可确认的页面操作。

## 模型调用与数据范围

复用服务端 sub2api 配置，`gpt-6-luna`，推理强度固定为 `xhigh`。每轮先使用严格结构化输出解析受控查询参数，服务端校验后执行预先编写的查询；有数据时再调用模型生成解释。模型不执行 SQL、不访问数据库、不决定用户身份。

金额、笔数、分类占比和月度差额由后端生成。解释只能引用服务端提供的占位符，由服务端替换。流式正文按完整句子校验后发布，不透传模型推理或半截占位符；解释出现未经核对的数值、未知引用、上游失败或超时，则移除补充解释并保留已核对的统计及提示。没有记录时直接返回明确说明，不生成消费原因或虚构趋势。兼容的普通消息接口仍在解释校验失败时使整轮失败。

规划请求只提供当前问题、最多六条最近问题及已保存的查询范围。解释请求只提供本轮统计与至多二十笔必要明细，不上传完整账单历史、OpenID 或 token。备注作为不可信数据处理。小程序隐私说明已补充按需发送统计/明细。

流式消息两次上游模型调用均使用 `stream=true`，整轮模型及统计处理共用 `CHAT_TIMEOUT_SECONDS`，默认二百四十秒，范围十至二百四十秒；旧普通消息接口继续使用 `LLM_TIMEOUT_SECONDS`，默认四十五秒。流式连接每十秒发送心跳，Nginx 关闭缓冲，前端连接超时为三百秒。流式不会消除首句前的推理等待，也不能保证永久连接；达到整轮预算时，已有统计就降级保存，没有统计则返回错误。

结束后用短事务原子保存问答和上下文；只有 `done` 事件代表已保存。失败或中断不保存半轮历史，不自动重试付费请求。客户端断连会取消上游生成并释放会话锁；如保存成功但最终事件丢失，可重新读取或使用相同消息 ID 重试。每用户每分钟最多十次新分析请求，重复读取已保存的相同消息不会重新调用模型。

## 接口

前缀 `/api/v1/assistant`，全部要求 Bearer token，响应使用 camelCase，均禁止客户端指定用户身份。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/conversations` | `{id, bookId, month}` 创建会话；固定 UUID 可重试 |
| GET | `/conversations?bookId=<UUID>&month=2026-10` | 当前账本及入口月份最近二十个已有回答的会话 |
| GET | `/conversations/{id}` | 最新二十轮完整问答，返回 `hasMore` |
| GET | `/conversations/{id}?before=<最早序号>` | 读取更早问答 |
| POST | `/conversations/{id}/messages` | `{id, text}` 提问；文本最多二百字符 |
| POST | `/conversations/{id}/messages/stream` | 同样的请求体，返回 `text/event-stream`；小程序使用此接口 |

流式事件：`status` 携带 `{text}` 进度；`snapshot` 携带 `{answer, result}` 统计快照；`delta` 携带 `{text}` 追加解释；`ping` 为空心跳；`done` 携带完整消息响应并覆盖预览；`error` 携带 `{status, detail}`，表示本轮没有确认完成。首包前的认证和会话访问错误仍返回普通 HTTP 错误，首包后的错误通过流内事件发送。响应禁止缓存，并设置 `X-Accel-Buffering: no`。

消息响应包含 `id`、`sequence`、`text`、`answer`、可选 `result` 统计卡、`context` 及 `createdAt`。`context` 为 `month`、可选 `categoryId`、`entryType`。历史回答保留生成时的统计快照，下一轮重新查询最新账单。

消息 ID 在单次发送及重试期间保持不变。已保存消息重复提交返回原回答；同一 ID 内容变化返回 409。Redis 短期会话锁防止并行追问打乱上下文，数据库版本与唯一约束保证整轮保存的一致性。会话最多一百轮，达到上限后开始新对话，旧对话仍可读取。

## 前端行为与验收

进入聊天时恢复当前账本及入口月份最近的对话，可从「历史」继续其他对话；「新对话」不删除旧历史。「查看更早的对话」分页读取。微信小程序使用 `enableChunked` 和 `onChunkReceived`，H5 使用 fetch 的流式读取；正确处理跨字节 UTF-8、跨分片 JSON 和 SSE 帧。统计及解释在请求结束前显示，新增正文时自动滚动。

等待期间禁止重复发送；失败后保留原消息和标记为未确认保存的预览，提供「重试这条消息」和「重新读取」。切换账号、账本或入口月份立即取消旧流、清理内存并忽略迟到的分片。体验区继续使用本地示例，不调用模型。
