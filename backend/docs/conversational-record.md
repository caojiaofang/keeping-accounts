# 文字聊天与图片记账

2026-10-27 已实现并验收，后端已发布至正式版本 `20261027T052736Z`，见[上线记录](releases/20261027T052736Z.md)；小程序新界面尚未上传体验版。本功能不新增数据库表，原 `/assistant/parse` 保留兼容旧客户端。

## 使用方式

「墨记助手 → 一句话记账」改为对话界面，底部可以输入文字，或点图片按钮拍照、从相册选取一张图片；支持只发图片，也支持图片配文字。图片选择后可以预览或移除，点击发送才请求识别。

- 可以连续说「午饭35元」「改成32元，是昨天的，用支付宝」，更新当前待确认草稿。信息缺失时继续补充即可，多笔指代不清时询问具体哪笔。
- 支付截图使用实付金额；小票默认按实付合计记一笔，商品保留为简短备注。不能把原价、优惠或余额重复记成收支。订单尚未完成、金额模糊、截图缺日期时要求补充，不猜测。
- 草稿可以手动修改、忽略、逐笔确认或批量确认。后续对话更新后，旧卡片保留为历史快照并禁用操作。模型不保存账单；文字说“确认”也仍需点击卡片。
- 已保存、已忽略的账单不再进入模型上下文，避免下一轮重新生成。失败的识别由用户主动重试，不自动产生付费重试。
- 保存结果未确认时，锁定草稿内容与编号，重试仍使用原内容及原 UUID；也可前往明细核对。不会把失败保存改成本地成功。
- 仅使用当前账本。切换账号、账本、开始新对话或关闭页面时，清空记账对话与图片，迟到的结果不能恢复旧内容。切换到「聊聊花费」再切回会保留本次记账内容。

体验区保留预置文字示例，任意文字及图片识别需要微信登录。记账聊天不保存到云端历史；「聊聊花费」原有云端历史功能保持独立。

## 接口与模型

`POST /api/v1/assistant/record` 使用 Bearer token，字段为 camelCase：

```json
{
  "bookId": "当前账本 UUID",
  "text": "改成32元，是昨天的",
  "history": [
    { "role": "user", "text": "午饭35元" },
    { "role": "assistant", "text": "已整理一笔待确认账单" }
  ],
  "drafts": [],
  "image": "data:image/png;base64,..."
}
```

`image` 可省略；`text` 最多200字符，文字与图片至少提供一项。`history` 最多6条，每条最多500字符，只允许 user/assistant；`drafts` 最多10笔，为当前待确认草稿，包含 `key`、`bookId`、`type`、`amount`、`categoryId`、`date`、可选 `time`、`note`、`account`、`accountDefaulted`，不包含 `status`、创建人或版本号。草稿账本必须匹配当前账本，key 不得重复。

返回 `{drafts, reply, clarification?}`。有 clarification 时保留旧草稿，并显示追问；若本次图片尚待补充，下一轮会再次发送该图。成功时用返回的完整草稿集合替换待确认集合；已有草稿保留 key，新增草稿由后端生成 UUID，拒绝模型伪造或重复的 key。明确取消全部草稿时返回空集合及提示。

复用后端配置的 `LLM_MODEL`、`LLM_API_MODE` 与固定 `xhigh`，不暴露前端密钥。图片按照 [OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision) 的 `input_image`（Responses）或 `image_url`（Chat Completions）格式内联发送，继续使用严格结构化输出。模型调用前后都检查账本权限，每分钟识别上限与旧接口共用10次。输出仍按正式账单规则校验金额、日期、分类及时间，确认走原 `/entries` 幂等接口。

模型不会收到登录 token、OpenID、账本 UUID 或完整账单历史，只收到当前文字、最近6条对话、当前待确认草稿与本次必要图片；上下文草稿中的 bookId 会在发送上游前移除。模型能读取当前草稿 key 用于关联更新，该编号不包含用户身份。

## 图片限制与发布

支持 JPG、PNG、WebP 静态图片，单张原始文件最多4 MiB、最多2400万像素。微信端选图采用 `uni.chooseMedia`；过大图片尝试压缩，读取前再次核对文件大小；H5 使用相册文件并在读取前检查体积。后端用 Pillow 验证真实格式、拒绝动画与无效图片，最长边缩到4096像素，透明区域铺白，转成不含 EXIF 等元数据的 JPEG 后发送。墨记不保存上传图片到磁盘或数据库，模型服务收到图片的处理受其服务约定约束。

发布时必须同时：

1. 更新后端镜像，安装 `requirements.txt` 新增的 Pillow。
2. 更新并校验 `backend/deploy/nginx.conf`：仅 `/api/v1/assistant/record` 放宽请求体到6 MiB，关闭请求缓冲及缓存；其他接口仍为1 MiB。Base64 会使图片体积增大约三分之一。
3. 更新微信小程序，并在小程序管理后台按实际使用的相册、拍照能力补充隐私保护指引。应用内登录与隐私说明已更新。
4. 真机验证相册、拍照、权限拒绝、键盘顶起、弱网重试及图片清晰度；H5 预览不能替代微信真机验收。

## 验收

离线检查已加入统一入口：`frontend npm run check:record` 覆盖上下文、图片补充、草稿更新、保存重试、账号/账本隔离及图片体积校验；后端 `tests/test_record.py` 覆盖图片内容、协议、权限、限流和输入输出契约。

真实模型验收只使用自制测试小票、模拟权限与限流服务，不访问真实用户账单或数据库：

```powershell
# backend 目录；会产生四次模型调用，测试不保存正式账单。
$env:MOJI_RUN_LLM_TESTS = '1'
.\.venv\Scripts\python.exe -m pytest tests/test_record_llm.py -q -s
Remove-Item Env:MOJI_RUN_LLM_TESTS
```

2026-10-27 已使用现有 sub2api 配置实测：缺金额追问、根据上文补全35元、保留 UUID 将金额改为32元并修改日期与账户，以及图片识别实付12.50元并排除原价/优惠/余额。两种 API 格式均有模拟协议测试，真实调用验证的是当前配置的 Responses 协议。

移动端 H5 另使用模拟接口验证文字发送、草稿修改、确认保存、选图预览及图片发送；仅使用隔离浏览器内的测试账号与示例账本。
