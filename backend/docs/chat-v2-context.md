# 聊聊花费 V2：可修正的对话上下文

2026-11-04，第 04 步交付。实现位于 `app/services/chat_v2_context.py` 和 `chat_v2_context_store.py`，依赖第 02 步的[筛选校验](chat-v2-filters.md)和第 03 步的[只读工具](chat-v2-tools.md)。本步提供后端服务，不接入模型编排、V2 API 或前端。

## 条件编辑与恢复

`ContextPatch` 是服务端内部输入，客户端仍只能提交消息及建议 ID。第 05 步的编排器负责把自然语言转换为受控修改，不允许模型直接改写整个历史对象。

```json
{"edits":[{"field":"keywords.include","op":"add","value":["咖啡"]}]}
```

| 操作 | 含义及边界 |
| --- | --- |
| `add` | 仅用于集合条件，追加后去重；“咖啡也算上”保留原词项。关键词仍遵循当前 `mode=any/all`，不会擅自改变匹配口径 |
| `replace` | 替换指定字段；“换成咖啡”不保留原包含词，其他字段继续继承 |
| `clear` | 恢复该字段的初始默认值；集合为空代表不限，日期回到入口月份，比较范围变为空 |
| `restore` | 指定同一会话的 `sourceTurnId`，恢复该轮成功上下文中的一个字段；跨会话、跨账号和跨账本来源拒绝 |
| `reset=true` | 全部筛选回到入口月份的默认条件，再执行本次 edits；原始问答与历史引用仍保留 |

可修改字段涵盖日期、收支、分类、关键词、账户、记账人、金额与开闭边界、星期、排除账单 ID 和比较区间；不包含身份、账本、事实或摘要。每次最多二十项编辑。

`sources` 用 `explicit/inherited/default` 记录各字段来源，恢复操作额外保存 `restoredFrom`。未触及的明确条件在下一轮标为继承。改变日期会清除旧比较区间，除非本次也明确设置比较范围；切换收支时清除不兼容的继承分类并返回说明，本轮明确给出的不兼容分类直接报错。清空金额界限同时恢复对应的包含等号默认值。

所有修改都经过原有日期、分类及组合筛选校验，并核对记账人和排除 ID 的账本权限。`revise` 仅生成包含 `expectedVersion` 的草稿，不写入会话；查询或回答失败不会提前改变成功条件。

## 持久化、隔离与失败处理

复用现有 `ChatConversation.context` 和 `ChatTurn.result/context` JSONB，不新增表或迁移。会话的 `context.schemaVersion=2` 为协议标记，数据库已有 `version` 用于已保存轮次并发控制，两者含义不同。第 07 步加入明确部分消息保存后，版本包含部分轮次，而权威上下文仍停留在上一成功状态。

消息 result 的持久化封装为：

```json
{
  "schemaVersion": 2,
  "payload": {"schemaVersion":2,"answer":"已核对范围。","completeness":"complete","missing":[],"cards":[],"factRefs":[],"suggestions":[]},
  "request": {"suggestionId":null}
}
```

`payload` 是完整 `AnswerPreviewV2`。该封装是数据库内部结构，接口仍使用 `TurnResponseV2`。原始问题、回答、结果及每轮完整成功上下文都保留，不用滚动摘要覆盖原问答。

`save_success` 的一个事务完成会话版本检查与更新、新消息插入、权限复核和提交；版本不一致返回 409。相同消息 ID、文本和建议 ID 返回原回答，不再次增加轮次；改变文本或建议 ID 则冲突。失败、取消和 `partial` 不进入成功保存路径。第 07 步新增的 `save_turn` 可保存部分消息，但不改变权威筛选、摘要及结果引用，详见[消息保存与恢复策略](chat-v2-api.md)。

每次读取绑定当前账号、会话和当前有权限的账本，当前共享成员也不能读取其他成员的私有聊天。只读操作完成即回滚释放事务，不持有事务等待模型。引用账单、保存前权限均重新核对。每个会话最多一百轮，沿用现有聊天的限制。

旧 V1 读取及列表已排除 V2 标记，避免旧写入路径误写新协议。V2 可显式只读适配旧 `month/categoryId/entryType`，旧回答仅按正文展示，不伪造 V2 卡片或引用。`fork_legacy` 校验权限后新建同账本 V2 会话，只继承筛选，清空新会话的摘要和结果引用，原会话不改写。

## “这笔”“这些”与新鲜数据

`resolve_reference` 默认从最近二十个已保存轮次向前查找最近一轮展示过账单的结果，也可指定同一会话的 `turnId/cardId/entryIds`。指定卡片或账单时必须提供来源轮次，指定 ID 必须在该轮所选卡片中真实展示过。

- `kind=entry` 必须唯一，多笔返回 `clarify` 与候选；不按金额或顺序擅自选择。
- `kind=entries` 可解析多笔已展示账单，最多二十笔；不会把当前页自动扩展为全部匹配记录。
- 账单删除、部分引用失效或超过上限时要求重新选择，不把余下结果冒充完整集合。
- 候选包含当前备注、日期、类型和真实引用。账单金额需通过新工具调用重新查询，旧卡片和历史回答始终只是生成时快照。

“还是刚才那类”可使用 `restore` 恢复已确认来源轮次的分类；来源无法确定时由后续编排器补充询问。本步不提供自然语言猜测器，也不直接执行排除操作；选择得到真实 ID 后才可修改 `excludedEntryIds` 并重查。

## 长度预算与滚动摘要

| 配置 | 默认值 | 范围 |
| --- | --- | --- |
| `CHAT_V2_CONTEXT_MAX_CHARS` | 16000 | 4000—32000，紧凑 JSON 的 Unicode 字符数，不是 token 数 |
| `CHAT_V2_CONTEXT_RECENT_TURNS` | 6 | 1—10，最近完整问答轮数 |

`for_model` 读取最新成功状态，组装完整筛选、比较范围、字段来源、结果引用、滚动摘要及最近问答。标记 `historyIsSnapshot/summaryIsRolling/omittedHistory`，明确历史的含义与省略情况。

摘要采用最多 2000 字符的完整 JSON 行笔记，记录序号、轮次 ID、问题与回答；超长回答整段替换为读取原轮次的说明，超预算按完整旧笔记移除，不截断金额或 UUID。`summaryThroughSequence` 表示已处理至该轮，摘要为滚动窗口，不表示从第一轮开始的全部结论仍在窗口内。最多保留二十个卡片引用。

模型输入超预算时依次移除整轮较早问答、完整旧摘要笔记、较早结果引用。保留当前全部筛选和最新完整回答，仍超预算则返回明确错误，不静默减少排除条件或截断正文。保存前也验证最低必要输入可以继续使用。原始历史不受输入裁剪影响。

此预算仅覆盖上下文；新问题、工具结果、系统提示和模型输出限额由第 05 步编排器另行纳入整轮预算。
