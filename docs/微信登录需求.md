# 墨记：微信登录需求

记录日期：2026-10-23。

状态更新（2026-10-24）：前后端登录已接入，包含微信登录页、体验入口、当前用户查询、启动恢复、退出登录和按用户隔离的本地记录。后端微信身份校验、重复用户识别和凭证失效已验证；账单业务的云端持久化和权限仍待实现。具体接口见[后端微信登录说明](../backend/docs/wechat-login.md)，运行方法见[前端说明](../frontend/README.md)。

## 1. 用户身份

- 小程序使用微信登录，通过微信返回的 OpenID 识别唯一用户。
- 当前小程序 AppID 为 `wx0f90babab478b2b6`。OpenID 的唯一性范围是当前小程序，数据库对 `(wechat_app_id, openid)` 设置唯一约束。
- 同一微信用户重复登录应识别为同一个用户，不能重复创建账号。
- 服务内部建议另设稳定的用户 ID，用于关联账本、账单、预算和聊天记录；OpenID 用于绑定微信身份。具体 ID 类型在建表时确定。
- 当前只要求单个微信小程序的身份识别，跨应用账号关联在出现相应需求时再设计。

## 2. 登录流程

```text
用户发起微信登录
    ↓
小程序通过 uni.login（微信端对应 wx.login）获取临时 code
    ↓
小程序将 code 发送给 Python + FastAPI 后端
    ↓
后端使用配置的 AppID、AppSecret 调用微信 code2Session
    ↓
后端根据 OpenID 查询用户，首次登录时创建用户
    ↓
后端签发墨记自己的登录凭证，返回用户基础信息
    ↓
小程序保存登录状态，后续业务请求携带登录凭证
```

头像、昵称和手机号属于独立的信息采集需求，不作为获取 OpenID 或识别用户的必要条件。页面不应把身份登录与头像昵称授权混为一谈。

## 3. 前后端职责

### 前端

- 提供微信登录入口、请求中的反馈以及失败重试提示，避免重复发起登录。
- 使用新获取的 code 请求后端登录接口，不把 OpenID 当作登录凭证。
- 恢复已有登录状态，并在后端判定凭证失效时引导重新登录。
- 提供退出登录操作，清理当前登录态；切换用户时按用户隔离本地缓存。
- 本地演示账单与真实用户数据区分，演示记录不自动写入登录用户的云端账本。

### 后端

- AppID 和 AppSecret 从后端配置读取，微信身份必须由服务端向微信验证。
- 不接受前端仅提交一个 OpenID 或用户 ID 就完成登录。
- 处理微信接口失败、code 无效或过期、网络超时等情况，失败时不生成有效登录态。
- 首次登录创建用户；通过数据库唯一约束处理重复或并发登录，保证同一微信身份对应同一用户。
- 管理登录凭证的有效期和退出失效。Redis 按既定环境前缀管理相应登录态，具体凭证形式在开发时确定。
- AppSecret 和微信返回的 session_key 只在后端处理，不返回前端，不记录到普通日志；业务接口验证墨记自己的登录凭证。

## 4. 数据权限和环境

- 账本、账单、预算、消费日历、统计和聊天会话均归属明确的用户。
- 当前用户由后端登录态确定，查询与修改数据时校验归属，不能信任请求自行声明的用户 ID。
- AI 记账和聊天分析也必须复用上述用户身份与权限规则。

| 环境 | PostgreSQL 数据库 | Redis key 前缀 |
| --- | --- | --- |
| 开发 | `keeping_accounts_dev` | `moji:dev:` |
| 正式 | `keeping_accounts_prod` | `moji:prod:` |

两个环境分别保存用户和登录态，开发凭证不能用于正式环境。

## 5. 验收要求

1. 首次微信登录能建立用户，重复登录仍对应原用户。
2. 不同微信用户的账单、账本和聊天记录相互隔离。
3. 无效、过期或已被使用的 code 不能登录成功，也不产生伪造用户。
4. 直接传入 OpenID 或用户 ID 不能冒用其他用户身份。
5. 未登录、凭证过期和退出后的业务访问按照鉴权规则处理。
6. 登录失败后可以重新获取 code 并重试，前端能展示明确的失败提示。
7. 切换用户不会显示前一个用户的本地缓存或会话内容。
8. 前端源码、编译产物和接口响应不包含 AppSecret 或 session_key。

## 6. 开发时细化

后端接口为 `POST /api/v1/auth/wechat/login`、`GET /api/v1/auth/me` 和 `POST /api/v1/auth/logout`，使用随机 Bearer token，默认有效期七天。内部用户 ID 使用 UUID。前端以登录页作为入口，保留无需登录的本地体验；账号使用独立的空账本与缓存，不自动导入体验记录。真实微信密钥只在后端环境配置中保存。

参考：[微信小程序登录流程](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)、[uni.login 文档](https://uniapp.dcloud.net.cn/api/plugins/login.html)。
