## 2. 产品目标与已确认需求

功能名称建议为「家庭预算」。使用流程：建立预算方案 → 提前安排月份 → 每月查看与微调 → 对照实际消费及储蓄进度。

已确认的需求：

1. 可以提前设置预算，不只设置一个月支出总额，还能设置具体用途。
2. 支持每月缴费、年度费用按月预留，以及为目标存钱。
3. 每月正常房贷 3,340 元；另每月计划存 4,200 元，用于一年攒约 5 万元后提前还贷，或半年积攒后提前还贷。
4. 设置一次后可在后续月份沿用，也能只调整某个月。
5. 计划金额、实际消费、实际预留和储蓄分别展示，避免重复统计。

第一版默认规则：每个账本可有一套家庭预算及其按月生效的版本；个人账本和共享账本都可使用。预算性质与账本名称无关，不要求必须创建名为「家庭」的账本。

## 4. 家庭预算示例

### 4.1 每月收入与分配

每月计划收入：15,600 元。

| 分组 | 项目 | 每月计划金额（元） | 性质 |
| --- | --- | ---: | --- |
| 固定缴费 | 房贷 | 3,340 | 当月支出预算 |
| 固定缴费 | 学费 | 1,100 | 当月支出预算 |
| 固定缴费 | 物业费 | 400 | 当月支出预算 |
| 年度费用预留 | 暖气、车险、年度医疗合计 | 520 | 预留；年度预计费用 6,100 |
| 储蓄 | 每月定存 | 2,000 | 储蓄；可不设截止目标 |
| 储蓄 | 提前还贷 | 4,200 | 储蓄；一年目标 50,000，或另设半年目标 |
| 生活费 | 生活费转账 | 1,000 | 用途额度，实际转账口径见第 5.6 节 |
| 生活费 | 其他日用购物 | 500 | 当月支出预算 |
| 生活费 | 李灿 | 400 | 当月用途额度，不自动绑定账号 |
| 生活费 | 李志 | 600 | 当月用途额度，包含话费，不自动绑定账号 |
| 生活费 | 燃、水、电 | 340 | 当月支出预算，包含电车充电 |
| 生活费 | 油费 | 300 | 当月支出预算 |
| 生活费 | 医疗 | 500 | 当月支出预算 |
| 生活费 | 人情 | 400 | 当月支出预算 |

汇总：

- 固定缴费：3,340 + 1,100 + 400 = 4,840 元。
- 固定缴费加年度预留：4,840 + 520 = 5,360 元，对应原清单的「固定支出合计」。
- 生活费八个子项：1,000 + 500 + 400 + 600 + 340 + 300 + 500 + 400 = 4,040 元。
- 储蓄：2,000 + 4,200 = 6,200 元。
- 每月总分配：4,840 + 520 + 6,200 + 4,040 = 15,600 元。
- 待分配：15,600 − 15,600 = 0 元，含义是收入已安排完，不是账户余额为零。

这些是需求与验收示例。不得自动写入已有用户的真实账本；可用于独立的演示数据或用户主动选择的模板预览。

### 4.2 年度预留与提前还贷

- 年度预计费用 6,100 元，除以 12 约为 508.33 元/月；用户选择每月预留 520，全年计划预留 6,240，比预计费用多 140，允许保存并显示差额。
- 提前还贷每月计划存 4,200，全年计划 50,400，比 50,000 目标多 400；半年计划为 25,200。半年目标由用户填写，可用 25,000 作为示例，不据此推断真实贷款安排。
- 年度费用可先合并为一个项目，也可拆为暖气、车险等，分别设置金额和缴费日期。拆分时不同时把合计项目计入预算。
- 年度医疗预留与生活费中的医疗是两个独立项目。实际关联同一笔医疗账单时只能选其中一个，不能重复归集。

## 5. 第一版业务规则

### 5.1 分组、项目与周期

第一版采用「分组 → 项目」两层结构，分组只汇总，不单独占用金额；所有分配只对叶子项目求和。生活费总额自动由子项求和。

项目性质分为：

| 性质 | 主要设置 | 执行展示 |
| --- | --- | --- |
| 当月支出 | 名称、每月额度、可选缴费日、备注 | 预算、已记支出、剩余额度、关联账单 |
| 周期费用预留 | 预计缴费金额、下次缴费日期、周期、每月计划预留 | 计划预留、实际预留、可用储备、实际缴费 |
| 储蓄 | 每月计划存入，可选目标金额及目标日期 | 本月计划与实际存入、可用储蓄、目标进度、使用记录 |

预算性质和周期分别保存。「每年」不自动等于「储蓄」，「每月」也不自动等于「已付款」。第一版支持费用每月、每半年、每年发生，储蓄可设半年或一年等明确的起止日期；具体日期字段与月末规则在第 01 步固定。

周期费用第一版以按月预留为主要方式，目标缴费月份单独展示预计付款。自定义任意复杂周期、自动推断工资日等后续扩展。

### 5.2 计划计算与金额精度

- 金额统一用整数分保存和计算，展示为元；服务端计算可信汇总，前端可提供即时预览。
- 月总分配 = 当月支出额度之和 + 当月计划预留之和 + 当月计划储蓄之和。
- 待分配 = 计划收入 − 月总分配。大于零显示待分配，小于零显示超出计划收入；允许保存不平衡方案并清楚提示，不强制凑成零。
- 计划收入独立于已经记账的实际收入，发工资或补记收入不自动改写预算。
- 年度预计金额除以 12 只产生建议，用户可以手动调整为 520 等金额。
- 选择精确均摊时，余下的整数分分配到具体月份，确保全年合计准确；不简单把四舍五入后的月额乘 12 当作年度金额。
- 首次使用或目标中途开始时，按有效起止月份和已有储备测算缺口，不能默认还有完整的 12 个月。建议月额与用户实际选定月额分别展示。
- 零额度、目标为空、金额上限、超额和舍入规则在第 01 步统一规定；不允许以浮点金额写库。

### 5.3 预算方案与月份

- 方案设置生效月份，后续月份继承有效方案，无需用户每月重新输入。
- 支持提前安排未来月份，预算查看与当前所选账本、月份一致。
- 「仅调整本月」只保存该月覆盖，不改变下一月及之后的方案。
- 「从所选月份起调整」保存新的生效版本；已有后续版本和单月覆盖不能被静默抹掉，先展示影响范围。默认适用到下一份明确安排的版本生效前。
- 过去月份的预算保留当时内容，不因当前方案变化而重算；第一版不提供直接改写过去月份预算的入口。
- 首次启用前的历史月份显示「未设置家庭预算」，不拿当前方案补造历史。方案已生效但从未打开过的月份，仍可按当时有效的版本还原。
- 已确认的月度预算保存快照；未来未确认的月份可以预览计算。同一月份重复确认或重试不生成多份数据，不依赖定时任务才能查看预算。
- 预算快照固定的是计划，不冻结实际账单。账单编辑、删除后，实际消费仍应按有效数据重新计算。

### 5.4 预留、储蓄与目标

- 计划存 4,200 不代表已经存入 4,200；月份推进不自动累加实际储蓄。
- 第一版通过「记录已预留／已存入」登记实际金额和日期，支持分多次存入及填写开始使用前的已有储备。
- 这是用途资金记录，不是银行账户余额，不读取银行卡流水，也不产生自动转账或扣款。
- 当前可用资金 = 期初已有储备 + 有效存入 − 有效使用，修正操作可追溯。期初储备只计一次，不能每月重新加入。
- 半年或年度目标至少区分「本期已筹集」「已用于目标」「当前可用」，提前还款后保留完成记录，不能把可用金额减少误显示为从未完成目标。
- 到期不自动标记已还款或清空储蓄。使用后可续建下一期目标，余款保留；转入下一期的余款不得重复计算。
- 开始时间临近缴费日、储备不足或实际支出超额时展示缺口；允许记录真实支出，不能为了保持余额为正而伪造存入或拒绝承认真实缴费。
- 有历史执行记录的项目采用停用或归档，历史仍可查看；不能通过删除项目抹去已有储备和使用记录。

### 5.5 账单关联与避免重复计算

- 设置预算、确认预留、记录储蓄均不自动创建收入或支出账单。
- 实际消费来自现有账单。第一版采用用户明确关联，不根据备注、姓名或分类静默认领历史账单。
- 第一版一笔支出最多关联一个叶子预算项目，按整笔金额归集；不支持把一笔账单拆分到多个项目。多个账单可归集到同一项目。
- 账单和预算项目必须属于同一有效账本；收入账单不能作为消费或资金使用关联。
- 当月支出项目按账单发生月份归集；周期预留及储蓄使用按所关联的资金项目和明确的目标期记录，避免跨年使用错归集。
- 年度费用支付或提前还贷，可关联已有支出账单，或通过正常记账流程新增后关联；减少储备的使用记录引用这笔账单，支出统计只计算原账单一次。
- 关联、取消关联、账单编辑或删除与资金使用必须一致更新。重试不重复扣储备，删除账单也不能留下仍然有效的扣减。
- 支出超过某项目额度时允许正常记账，显示超额；未关联支出集中展示，不把它当成没有发生。
- 缺少账单只能显示「未记录」，不能断言现实中尚未付款。预算剩余额度不等于真实银行余额。
- 退款沿用项目现有收入口径，第一版不自动冲减预算支出或回补储备；需要修正时通过明确操作完成并保留记录。

### 5.6 生活费转账与成员用途额度

示例里的「生活费转账」「李灿」「李志」首先是用户命名的分配用途，不自动认定是消费分类、付款人、记账人或真实资金转账。

- 在家庭内部把钱交给另一位成员，本身可只登记分配用途；之后发生的实际购物、餐饮等由真实账单体现。
- 如果用户选择把交付生活费本身作为最终支出记录，就不能再把同一笔钱的后续消费重复记入共同消费；界面需说明所选记账口径。
- 第一版不扩展成银行转账或家庭成员账户余额系统，不能因为填写「转账」就自动创建支出。

### 5.7 权限、隔离与可靠性

- 个人账本拥有者管理自己的预算、资金记录和关联。
- 共享账本有效成员可查看预算和执行；默认只有创建者能修改方案、单月预算、储备和目标。
- 普通成员可按原有账单权限，为自己可编辑的支出选择或取消预算关联；创建者可处理全部共同账单。关联操作产生的使用记录由同一事务受控维护，成员不能直接随意增减共同储备。
- 复用共享生命周期的权限复核，退出、移出、转让和解散后的访问与写入规则一致；用户、账本和记账人由后端可信上下文绑定。
- 创建与确认支持幂等重试，编辑带版本，冲突后读取最新数据，不静默覆盖其他设备的修改。
- 同月确认、同一账单关联、同一资金记录修改需要并发保护；关键读写采用一致的账本锁顺序，避免与现有共享操作相互死锁。
- 云端失败不伪装本地保存成功；缓存按接口地址、账号和账本隔离，切换账号后丢弃迟到响应。
- 本地体验使用独立演示预算，登录后不自动上传或混入真实预算。

## 6. 页面与交互范围

### 6.1 入口和月度总览

从首页预算卡、「我的」预算入口进入，沿用所选账本和月份。共享成员可进入只读总览，编辑操作根据权限显示。

未启用家庭预算时保留原有月预算，并提供「设置家庭预算」入口；配置新方案不将旧预算值擅自解释为收入或明细。

启用后预算卡展示「计划收入／已分配／待分配」等计划指标，详情分别展示实际消费与储蓄执行，不继续把整个家庭分配额标成「还可支出」。原有明细、统计和日历的收支仍来自真实账单。

总览内容：

- 月份与账本切换，计划或预览状态。
- 计划收入、总分配、待分配或超分配金额。
- 固定缴费、年度预留、储蓄、生活费等可展开分组。
- 各项预算与执行、未关联实际支出、近期缴费或目标日期。
- 「编辑本月」「调整后续方案」「新增项目」等符合权限的入口。

### 6.2 方案设置与项目编辑

设置计划收入、生效月份、分组和项目。选择项目性质后只显示必要字段，金额变动即时预览总分配；保存前说明影响月份。

年度费用允许填写预计总额、下次缴费日期及手动月预留；储蓄允许填写目标和已有储备。停用有执行记录的项目时保留其历史与余额。

### 6.3 项目详情与执行

当月支出展示关联账单和剩余额度；预留、储蓄展示计划、实际存入、使用记录、可用资金和目标进度。

提供记录存入、关联缴费或还贷账单、修正执行记录等入口；共同账本普通成员只开放其有权操作的部分。所有「已存」「已付」都应能追溯到明确记录。

## 7. 数据与接口设计方向

第 01 步已形成[正式契约与纯计算说明](../backend/docs/family-budget-contract.md)，固定字段、路由、状态、金额／日期规则和事务边界。下表为责任概览，后续实现以正式契约为准。

| 概念 | 责任 |
| --- | --- |
| 预算方案及生效版本 | 账本归属、计划收入、生效月份、版本与项目配置 |
| 稳定预算项目 | 名称、分组、性质、周期及状态；跨方案修改仍能追踪同一储备或储蓄用途 |
| 月度预算与项目快照 | 当月计划、来源版本、单月覆盖、确认状态；唯一对应账本和月份 |
| 用途资金记录 | 期初储备、实际存入、使用及修正；引用稳定项目，不因改名、换方案断开余额 |
| 目标期 | 起止日期、目标金额、期初分配和完成／使用情况；支持续建及余款衔接 |
| 账单关联 | 原账单与唯一预算项目的关联；需要使用储备时保持事务一致 |

接口至少覆盖：读取及保存方案、预览和确认月预算、单月调整、项目停用、资金执行记录、账单关联和月度汇总。查询必须区分「未设置」「预览」「已确认」，并说明实际数据的更新时间。

服务端负责金额、日期、权限、版本和幂等校验；不会让前端直接提交可信汇总或任意用户身份。新增模块建议独立放在后端 budget 模型/schema/service/API 和前端 budget 类型、服务及 store 中，避免继续扩大 `ledger.ts`。

迁移采取增量方式，不修改已经发布的旧迁移。暂不增加银行账户、支付集成、AI 自动操作或新的记账类型来实现预算。

## 9. 核心验收场景

| 场景 | 预期结果 |
| --- | --- |
| 完整家庭示例 | 计划收入与总分配均为 15,600，生活费为 4,040，待分配为 0 |
| 未花钱、未存钱 | 仅有计划，实际消费和实际存入不会自动增加 |
| 精确均摊 6,100 | 各月按整数分分配，全年合计准确 |
| 自定每月预留 520 | 年计划为 6,240，显示相对预计费用多 140，允许保存 |
| 每月存 4,200 | 年计划为 50,400，半年为 25,200，实际进度依赖存入记录 |
| 存 50,400 后提前还 50,000 | 支出只计算真实还贷账单一次，可用余款为 400，目标历史保留 |
| 年度缴费临近但储备不足 | 显示缺口，不假定已经攒足；真实缴费仍可记录 |
| 某月临时多给人情 200 | 仅当月分配增加 200，后续月份不变，超分配提示正确 |
| 后续学费变为 1,200 | 从指定月份生效，历史预算及此前执行不变 |
| 生效前历史月份 | 显示未设置，不自动套用当前方案 |
| 同一账单重复关联 | 最多归集到一个项目，不重复扣储备 |
| 删除或修改关联账单 | 实际汇总、资金使用同步修正，无残留扣减 |
| 生活费内部转交后再购物 | 按用户明确选择的口径记录，不能因预算自动制造双份支出 |
| 共同成员退群或被移出 | 不能继续读写失效账本；旧页面不能凭缓存绕过权限 |
| 同月确认、存入请求重试 | 月快照、执行记录及余额均不重复 |
| 跨账号、跨账本和断网 | 数据隔离，失败可重试，不展示伪成功 |
| 旧客户端或未启用新预算 | 原月预算及记账接口仍按原口径工作 |
